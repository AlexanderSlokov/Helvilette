# Manifest `v1alpha2`: one `helvilette.yml` per repository, listing playbooks, plan by default

ADR-0008 D3 retired `spec.repo` and deferred the new schema to its own record.
This is that record. The decisions are D1 to D10.

## Context and Problem Statement

In `v1alpha1` (ADR-0002), a manifest describes **one** playbook in **another**
repository:

- `spec.repo` and `spec.branch` name the playbook repository.
- `spec.playbook` names the file inside it.
- `spec.nodeGroups` maps node labels to Ansible variables.

Othela walks a separate fleet repository, finds one `helvilette.yml` per
subdirectory (ADR-0003, ADR-0006), and dispatches jobs.

ADR-0008 removes that middleman. The agent clones one repository, named in its
own `agent.yaml` like `ansible-pull -U`, and reads the manifest from that same
repository. So:

- `spec.repo` and `spec.branch` point to the repository the file already sits
  in. They are now redundant, and a second source of truth if they disagree.
- One repository usually holds several playbooks (`baseline.yml`, `web.yml`), so
  one playbook per manifest no longer fits.
- ADR-0008 D9 requires the manifest to say which playbooks may apply on their
  own, and nothing in `v1alpha1` can say it.

## Decision

### D1. One file, at the repository root

The agent reads exactly one `helvilette.yml`, at the root of its checkout. It
does not walk subdirectories. The doctrine asks for configuration in one place
(section 4.3.3), and `ansible-pull` also reads one repository with one entry
point.

ADR-0006's near-miss warning stays: a root file named `helvilette.yaml`, or any
other case variant, produces a warning and is not loaded.

### D2. The Kubernetes envelope stays

`apiVersion`, `kind`, `metadata` and `spec` stay. The doctrine rejects copying
Kubernetes' **topology** mechanically (control plane, agents, a state store).
It does not reject Kubernetes' file format. Principle 4 asks the opposite:
interfaces should be versioned, and should speak the ecosystem's common
language so parts can be swapped. Anyone who has read a Kubernetes manifest can
read this one.

- `apiVersion: helvilette.naughtian.org/v1alpha2`.
- `kind: PlaybookDeployment`, unchanged.
- `metadata.name` is required. `metadata.description` and `metadata.labels` are
  optional.
- `metadata.namespace` is removed. It never had a function, and namespaces are a
  Phase 3 feature at most.

### D3. `spec.playbooks` is an ordered list

```yaml
apiVersion: helvilette.naughtian.org/v1alpha2
kind: PlaybookDeployment
metadata:
  name: edge-fleet
  description: Baseline on every node, nginx on edge proxies
spec:
  playbooks:
    - name: baseline
      playbook: baseline.yml
      apply: auto
      nodeGroups:
        - name: all-nodes
          nodeSelector:
            managed: "true"
          ansible:
            extra_vars:
              chrony_pool: ntp.ubuntu.com

    - name: web
      playbook: web.yml          # no apply: this playbook only plans
      nodeGroups:
        - name: standard-proxies
          nodeSelector:
            role: edge-proxy
          ansible:
            extra_vars:
              nginx_http_port: "80"
            vault-password-file: /etc/helvilette/vault-pass
```

Each entry has:

- `name`: required, unique within the file. Run records and `explain` use it.
- `playbook`: required. A path relative to the repository root. Absolute paths
  and paths that leave the repository through `..` are rejected at load time.
- `apply`: `auto` or `plan`. Optional; see D4.
- `nodeGroups`: required, at least one entry; see D5.

### D4. `plan` is the default

A playbook with no `apply` key only plans: the agent runs the check, writes the
record, and changes nothing. To change machines on its own, a playbook must say
`apply: auto`, and that line arrives in a signed commit (ADR-0008 D9). This
follows the doctrine's safe defaults (section 3.2): nothing unexpected happens
where nothing was configured.

Any other value of `apply` is rejected at load time, with the value and the two
accepted ones in the message.

### D5. `nodeGroups` keep their `v1alpha1` shape

Each playbook carries its own `nodeGroups`: a `name`, a `nodeSelector`, and an
`ansible` block with `extra_vars` and `vault-password-file`. The validation in
`pkg/manifest` and ADR-0004 (no two groups with identical selectors) apply
within each playbook.

Two changes:

- `vault-password-file` is a path to a file **on the node**, passed straight to
  `ansible-playbook --vault-password-file`. In `v1alpha1` it named an entry in
  `spec.vault`, which is removed (D8).
- A node that matches several groups of the same playbook gets the first match in
  file order, as before. Rejecting overlapping subsets is still deferred
  (ADR-0004), and the record names the group that was chosen.

### D6. A node matching several playbooks runs them all, in file order

This works like plays in one Ansible playbook: order is meaningful, and a later
playbook may depend on an earlier one.

- Each playbook goes through its own cycle: check, apply if `auto`, record.
- If a playbook fails (check or apply), the playbooks after it do not run. The
  record names each one as "not run, because `<name>` failed".
- The next cycle starts again from the first playbook.

### D7. No `helvilette.yml`: the `ansible-pull` fallback, in plan mode

Without a root `helvilette.yml`, the agent picks the first of `<fqdn>.yml`,
`<hostname>.yml` and `local.yml` that exists (ADR-0008 D2), and runs it in
**plan** mode. An existing `ansible-pull` repository therefore works on day one:
it is checked and recorded, but nothing is changed until someone adds a
`helvilette.yml` that says `apply: auto`.

If none of the three files exists either, the agent does nothing and says so
(D9).

### D8. Removed from `v1alpha1`

| Field | Why it goes |
| --- | --- |
| `spec.repo`, `spec.branch` | The file sits in the repository; the URL and branch are in `agent.yaml` (ADR-0008 D2) |
| `spec.playbook` | Replaced by `spec.playbooks[].playbook` |
| `spec.vault` (`exported`, `hashicorp_vault`) | Ansible's own lookups already do this; secrets come from Kallisto through the Vault lookup. BACKLOG lists it under "Not doing" |
| `metadata.namespace` | No function (D2) |

The parser decodes with `KnownFields(true)`, so a removed field is an error, and
the message names the field and what replaced it. The agent rejects a
`v1alpha1` file with a message pointing to this ADR. Othela, frozen, keeps
reading `v1alpha1` until Phase 3.

### D9. A node that matches nothing does nothing, visibly

If no `nodeGroup` of any playbook matches the node's labels, the agent runs
nothing. It logs one line per cycle with the node's labels, and
`helvilette status` shows "no playbook selected for this node". This is a
declared state, not an error: a fleet can include nodes that only some
playbooks target.

### D10. `probes` is reserved

Probes are core (ADR-0008 D7), but their schema is not designed yet. The key
`probes` inside a `nodeGroup` is reserved. Until its ADR lands, a manifest that
uses it is rejected with "probes are not supported yet", not with a generic
unknown-field error. This keeps a probe the operator wrote from being silently
ignored.

From `v1` on, the manifest only gains fields (ADR-0008 D3). Until then,
`v1alpha2` may still change, through an ADR.

## Consequences

### Positive

- One repository, one file, one entry point. The operator reads one file to know
  what a node will run.
- Day one with an existing `ansible-pull` repository is safe: plan only, with
  records.
- Automatic change is opt-in per playbook and signed.

### Negative and breaking

- Every `v1alpha1` manifest must be rewritten. The e2e fixtures move from the
  fleet repository to a root `helvilette.yml` in each playbook repository when
  the agent starts reading manifests (issue #43, item 1).
- `pkg/manifest` gains `v1alpha2` types and validation alongside `v1alpha1`,
  until Othela is either migrated or retired in Phase 3.
- `spec.vault` users, of whom there are none outside the fixtures, lose the
  custom secret types.

### Neutral

- The `nodeSelector` semantics (every listed label must match exactly) and
  ADR-0004 are unchanged.
- `extra_vars` stay string to string, as in `v1alpha1`.
