# Every path the playbook loader declines to load emits a log line

## Context and Problem Statement

Issue #34 was filed after a First Light run in which Othela printed
`{"count":0,"message":"scan complete"}` and stopped. A manifest was on disk. No
warning explained why it had not been loaded, and the operator had no way to
tell which of several possible causes applied: wrong directory, wrong filename,
unreadable permissions, or a manifest that failed validation.

The loader in `pkg/playbook/loader.go` logged exactly two things: a `Warn` when
`manifest.ParseFile` rejected a file, and an `Info` carrying the final count.
Everything else — directories skipped, files passed over, the base directory
actually scanned — was invisible. `count: 0` was a number with no context behind
it.

The First Light logbook (`vagrant/docs/FirstLight-Logbook.md`) drew the general
rule from this:

> Any conditional logic that results in skipping data processing, dropping
> events, or canceling tasks MUST emit a descriptive log entry.

That rule was written as feedback. This ADR makes it binding for the loader.

A related question surfaced while implementing it: a manifest named
`helvilette.yaml` parses cleanly and is what an operator coming from Kubernetes
reaches for, but the loader matches `helvilette.yml` exactly. Two options:

1. **Accept both spellings.** Convenient, but it widens the v1alpha1 contract and
   leaves two names to document, test and reason about.
2. **Keep one name and say so loudly.** Consistent with ADR-0002 and ADR-0004,
   which both chose to reject rather than to guess.

## Decision

**Every path the walk declines to turn into a playbook emits a log line naming
the path and the reason.**

| Situation | Level | Field |
| --- | --- | --- |
| Dotted directory skipped (`.git` and friends) | `debug` | `skip_reason=hidden_dir` |
| Ordinary file that is not a manifest | `debug` | `skip_reason=not_a_manifest` |
| Manifest rejected by validation | `warn` | `skip_reason=parse_rejected` + the error |
| Filename differs only in case or extension | `warn` | `found`, `expected` |
| Path unreadable during the walk | `warn` | the walk error |

**The closing line carries the numbers behind the count**: `base_dir`,
`files_examined`, `skipped`, `rejected`, `near_misses`, `expected_filename`.

**A count of zero is a warning, not an information line.** Zero playbooks means
no node will be dispatched anything. That is an operational state worth raising,
not a neutral fact.

**`helvilette.yml` remains the only accepted filename** (option 2 above).
`helvilette.yaml`, `Helvilette.yml` and any other case or extension variant are
reported as near misses with a `warn` naming both what was found and what was
expected, and are not loaded.

## Consequences

### Positive

- The `count: 0` that prompted issue #34 now arrives as a warning stating which
  directory was scanned and how many files were looked at, which separates
  "wrong directory" from "right directory, wrong filename" without a rebuild.
- `--log-level=debug` produces a complete account of the walk, so a permission
  or pathing problem is diagnosable from logs alone.
- A near-miss filename fails loudly at the moment of the mistake instead of
  turning into a node that never receives work.

### Negative

- Debug-level output is noisier: a fleet repository with many files emits one
  line per file. Acceptable — it is off at the default level, and the alternative
  is the silence issue #34 was filed about.

### Neutral

- The loader's map is now guarded by a mutex. `Scan` runs on Othela's fleet-sync
  goroutine while `Get` and `GetByName` are reached from HTTP handlers; the
  previous code raced. Unrelated to logging, found in the same pass.
- `pkg/log` gained `SetOutput`, which redirects all output and returns the
  previous destination. Log lines are now part of the loader's contract, so
  tests have to be able to read them back.

## Related

- Issue #34: playbook loader silently skips `helvilette.yml` manifests.
- Issue #31: Othela startup logs standardised to structured JSON — the same
  observability push, from the same First Light run.
- ADR-0002: manifest schema identity, validated on load. The rejection path this
  ADR makes visible is the one ADR-0002 introduced.
- ADR-0004: overlapping `nodeGroup` selectors rejected rather than silently
  first-matched. Same preference for loud failure over a quiet guess.
- ADR-0005: fleet sync, which calls `Scan` on every poll.
